Corrections — Fix Before Phase 2

01 · Unverified dependency versions

fastapi 0.141.1, langgraph 1.2.10, sqlalchemy 2.0.51, alembic 1.18.5, redis 8.1.0, uvicorn 0.52.0 — confirm these are the real installed versions, not typos or hallucinated numbers.

pip list --format=freeze | grep -Ei "fastapi|langgraph|pydantic-ai|sqlalchemy|qdrant|langchain|redis|uvicorn|alembic|playwright"
02 · App cannot boot without external services

init_redis() / init_qdrant() run in the FastAPI lifespan with no fallback. Filed as a "suggestion," but it's the difference between a runnable handoff and a broken one.

Wrap both init calls in try/except with a logged warning in dev mode; only hard-fail in a prod-flagged environment.

03 · Admin auth stub is a security hole, not a TODO

require_admin() always returns dev-admin. That's an open admin panel sitting behind zero real gate.

Add a loud runtime warning banner on every admin route while the stub is active, and put "DO NOT DEPLOY" in the docstring of require_admin() itself — not just in a markdown file that can get lost.

04 · Test status overclaims coverage

"13/13 PASSED" covers Pydantic schema validation only — no DB, no graph, no API, no websocket.

Relabel as "Unit tests (schemas only)" and open a tracked gap for integration + graph tests before Phase 7 is treated as the first time tests are written.

05 · Local-machine-only reference paths

C:\Users\Admin\.gemini\antigravity-ide\brain\...\implementation_plan.md will not resolve for an agent on a different machine or container.

Copy implementation_plan.md, cli_mcp_spec.md, and task.md into /docs in the repo itself. A handoff doc should never depend on a path only the sender can see.

06 · Scraper has no compliance guardrail

Phase 2's Playwright crawler has no mention of robots.txt, request throttling, or ToS review for target sites.

Add a one-paragraph scraping policy to Phase 2's spec before implementation starts — rate limit, user-agent identification, and a documented allowlist of domains.

Setup — Run In This Order

This is the sequence a human or an AI coding assistant should follow to get from a fresh clone to a running dev environment. Each step is a gate — don't proceed past a failing step.

1Confirm environment

python --version          # expect 3.14.x
pip list --format=freeze  # cross-check against ARCHITECTURE.md — see correction 01

2Bring up infrastructure

docker compose up -d postgres redis qdrant ollama
docker compose ps          # all 4 should show "healthy" before continuing

3Verify Postgres

psql -U malluser -d mallrag -c "\dt"   # expect: no tables yet, connection succeeds

4Run migrations

alembic revision --autogenerate -m "initial schema"
alembic upgrade head
psql -U malluser -d mallrag -c "\dt"   # expect: 7 tables now present

5Install browser binaries

playwright install chromium

6Run what's testable today

python -m pytest tests/test_schemas.py -v   # expect: 13 passed

7Boot the app

uvicorn app.main:app --reload
# if this crashes on Redis/Qdrant init, that's correction 02 — fix before continuing
  • Pass 1 — dependencies installed, versions verified against real pip output
  • Pass 2 — docker services healthy
  • Pass 3 — migrations run, 7 tables confirmed in psql
  • Pass 4 — app boots cleanly with all services up
  • Pass 5 — app boots (degraded) with services down, per correction 02
